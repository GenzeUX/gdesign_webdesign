# G. DESIGN — Digital & AI Studio

Многостраничный сайт студии: Next.js App Router, React, TypeScript, Tailwind CSS, Motion, Three.js, Lenis и Zod. Русский интерфейс, локальные шрифты Manrope и Space Grotesk.

## Запуск

Установите поддерживаемую LTS-версию Node.js (не ниже 20.9), склонируйте репозиторий и выполните:

```powershell
npm.cmd ci
Copy-Item .env.example .env.local
npm.cmd run dev
```

Откройте адрес, указанный в терминале, обычно http://localhost:3000. В Windows также можно открыть `START.cmd` двойным щелчком. Команда `npm.cmd` позволяет запускать npm без изменения политики выполнения PowerShell.

Если защищённая папка «Документы» или OneDrive блокирует создание файлов, используйте обычную папку разработки вне OneDrive.

## Production и проверки

```powershell
npm.cmd run build
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
npm.cmd start
```

На Linux/macOS используйте `npm` вместо `npm.cmd`. Production build создаёт все страницы и серверный endpoint для необязательного режима бота. Основной контактный путь — локальная подготовка сообщения и переход в личный Telegram.

Браузерные проверки используют Playwright и установленный Microsoft Edge. `npm.cmd run verify:browser` запускает production-сервер и проверяет базовые сценарии. `node scripts/verify-production-visual.mjs` проверяет световую сцену, reduced motion и адаптивность. `node scripts/verify-production-refinement.mjs` проверяет подвал, SVG-иконки, фоновые сцены и форму с перехваченными ответами API — реальные обращения не отправляются. `node scripts/verify-extension-hydration.mjs` запускается против development-сервера и проверяет совместимость с атрибутами браузерных расширений. Скриншоты остаются в игнорируемой папке `test-results/`.

## Публикация в Vercel

Импортируйте этот репозиторий в свой Vercel, выберите Next.js и корень репозитория. Команды установки и сборки заданы в `vercel.json`: `npm ci` и `npm run build`. Используйте поддерживаемую LTS-версию Node.js в настройках проекта.

После подключения Git последующие push в production-ветку могут автоматически запускать новые публикации. Для публичной production-ссылки отключите защиту доступа только в соответствии с желаемыми настройками проекта.

Публичный адрес для canonical, Open Graph, robots и sitemap определяется автоматически из `VERCEL_PROJECT_PRODUCTION_URL`, затем `VERCEL_URL`. Для собственного домена задайте `NEXT_PUBLIC_SITE_URL=https://ваш-домен` и пересоберите проект. Preview-адреса допускаются формой только при точном совпадении с доменами, предоставленными окружением Vercel; произвольные поддомены не разрешаются.

## Настройка формы

По умолчанию `CONTACT_DELIVERY=telegram`: посетитель заполняет короткий бриф, получает текст и сам отправляет его в чат @gen_design. Данные не отправляются на сервер сайта, Telegram-клик не считается доставленной заявкой. Для этого режима токены не нужны.

Необязательный режим `CONTACT_DELIVERY=bot` включается отдельно после настройки получателя, правил обработки данных и проверки доставки.

В `.env.local` для разработки либо Environment Variables в Vercel задайте:

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен вашего Telegram-бота |
| `TELEGRAM_CHAT_ID` | ID чата для заявок |
| `UPSTASH_REDIS_REST_URL` | Общий Redis REST endpoint для лимитов между serverless-инстансами |
| `UPSTASH_REDIS_REST_TOKEN` | Секрет доступа к Redis |
| `TRUST_PROXY` | `true` только за доверенным прокси, перезаписывающим `x-forwarded-for` |
| `NEXT_PUBLIC_SITE_URL` | Необязательный полный публичный адрес для своего домена |

Создайте бота через BotFather, начните с ним диалог или добавьте его в нужный чат и получите ID чата. После настройки проверьте реальную доставку самостоятельно. Секреты никогда не должны иметь префикс `NEXT_PUBLIC_`.

Если бот не настроен, сайт использует личный Telegram с подготовкой черновика. В режиме бота подтверждение доставки отображается только после `ok: true` от Telegram API; подготовленный черновик никогда не выдаётся за отправленную заявку.

Серверный endpoint для режима бота защищён валидацией Zod, honeypot, проверкой времени заполнения, Origin, размера и типа тела, ограничением частоты и блокировкой повторных заявок. По умолчанию ограничитель хранится в памяти одного процесса; для нескольких процессов и serverless используется общий Redis. Ошибка Redis закрывает доставку с понятным сообщением. Неопределённый сетевой результат сохраняет временную блокировку повторной отправки.

## Страницы и структура

Маршруты: `/`, `/services`, четыре страницы `/services/[slug]`, `/projects`, восемь страниц `/projects/[slug]`, `/about` — всего 16 основных страниц.

- `src/app/` — страницы, layout, API, metadata, sitemap и robots.
- `src/content/studio.ts` — услуги, контакты и типизированные данные проектов.
- `src/components/sections/` — блоки страниц и форма.
- `src/components/graphics/service-icons.tsx` — авторская SVG-иконография.
- `src/components/three/` — световое поле и ленивые фоновые сцены.
- `src/components/motion/` — анимации и плавная прокрутка.
- `src/lib/` — серверная логика заявок и разрешение доменов.
- `public/brand/`, `public/images/` — айдентика и статичный кадр сцены.

WebGL ограничивает DPR, останавливается вне видимости и в скрытой вкладке, использует упрощение для мобильных. Для reduced motion, экономии трафика и недоступного WebGL предусмотрены статичные версии. Hero использует собственное процедурное световое поле; материалы чужих сайтов не копировались.

## Контент перед коммерческой публикацией

Портфолио содержит восемь кейсов из канала https://t.me/portfolio_sites_gen_design. Данные находятся в `src/content/projects.ts`, исходные 16 изображений — в `public/images/projects/`. По согласованию с владельцем добавлены восемь AI-реставраций обложек: по последующему запросу владельца видимые подписи убраны, ссылки на оригиналы сохранены; подробности в `RESTORED-IMAGES.md`. Страницы `/projects/[slug]` и sitemap создаются из общего списка. На главной показаны две избранные работы. Результаты приведены по исходным публикациям, ссылки на них сохранены в каждом кейсе. Сбор данных серверной формой требует отдельно согласованных сведений об операторе и условиях обработки.

Направление C со сдержанностью A описано в `REFINEMENT.md`, подключение и ограничения аналитики — в `ANALYTICS.md`. Аналитика выключена на preview. Перед включением в production нужно активировать Web Analytics в панели Vercel; платные события не включаются автоматически.

Секреты, зависимости, сборки, локальные отчёты и скриншоты исключены из Git и пакета Vercel. Репозиторий: https://github.com/GenzeUX/gdesign_webdesign.
